# Runtime link inventory — extension DEX compatibility shims (V811-RT-A)

Evidence-based inventory of what third-party extension DEXes need from the host
process at class-load/link time, and what the `:core:extension-api` shim module
provides. Generated by `core/extension-api/tools/inventory.py` (stdlib-only,
reproducible); raw dexdump evidence and per-extension lists are checked in under
`core/extension-api/src/test/resources/inventory/` and asserted by
`InventoryLinkContractTest`.

## Method

1. **Fixture**: `data/extension/src/test/resources/keiyoushi-index.pb` (gzip protobuf
   index from HO-V811-FIX-2; 1435 extensions) pins the three audited extensions and
   their exact APK file names.
2. **Download**: APK base URL `https://raw.githubusercontent.com/keiyoushi/extensions/repo/apk/`
   (the layout published by https://github.com/keiyoushi/extensions/blob/repo/README.md;
   the fixture stores the equivalent version-pinned GitHub release URLs). Both sources
   served byte-identical APKs (sha256 below stable across fetches). APKs and extracted
   `classes.dex` + full `dexdump -f -d` texts are kept for later agents in
   `C:\Users\paele\AppData\Local\Temp\opencode\extdex\`.
3. **Extraction**: `dexdump.exe` from `C:\Users\paele\AppData\Local\Android\Sdk\build-tools\35.0.0\`
   plus a direct DEX header parse (string/type/proto/method/field id tables) in
   `tools/inventory.py`. Referenced types minus classes bundled in the extension DEX
   itself minus JDK/Android-framework packages = **host-provided requirement set**.
   Members (method/field refs) and the virtual methods each extension *defines* on its
   `HttpSource` subclass (i.e. every member it overrides) are captured separately
   (`*.members.txt`, `*.source-virtuals.txt`, `*.external-members.txt`).
4. **Reference ABI**: keiyoushi/extensions-lib v1.6, commit `42255ee5fa`
   (https://github.com/keiyoushi/extensions-lib) — the exact library the audited
   extensions compile against (`tachiyomi-lib-v16` per extensions-source
   `gradle/libs.versions.toml`); Mihon's source-api for runtime behaviors
   (id generation, default headers, setUrlWithoutDomain, SMangaImpl/SChapterImpl).

## Shim set (union, 23 eu.kanade.* types — all provided by :core:extension-api)

`network/HttpException`, `network/NetworkHelper`, `network/OkHttpExtensionsKt`,
`network/RequestsKt`, `source/ConfigurableSource`, `source/SourceFactory`,
`source/online/HttpSource`, `source/model/Filter` (+ `Header`, `Separator`, `Select`,

Key signature evidence (full lists in `inventory/*.members.txt`):

* `Source`/`HttpSource` entry points are the **v1.6 suspend API** only —
  `getPopularManga/getLatestUpdates/getSearchManga/getMangaUpdate/getPageList`
  (all `(…, Continuation)Object`). No DEX references a callback-style
  `getMangaDetails/getChapterList/getImageList` or `fetchMangaDetails`; the task's
  candidate list was verified and those members are **not required**.
* Overridden ABI members (from `*.source-virtuals.txt`): `getBaseUrl`, `getChapterUrl`,
  `getClient`, `getDisableRelatedMangas`, `getDisableRelatedMangasBySearch`,
  `getFilterList`, `getId`, `getLang`, `getLatestUpdates`, `getMangaUpdate`,
  `getMangaUrl`, `getName`, `getPageList`, `getPopularManga`, `getSearchManga`,
  `getSupportsLatest`, `getSupportsRelatedMangas`, `fetchRelatedMangaList`,
  `headersBuilder`, `imageRequest`, `setupPreferenceScreen` — all declared by the shim
  hierarchy (`HttpSource`/`CatalogueSource`/`Source`/`ConfigurableSource`).
* Model constructor defaults pinned by `$default` synthetics in the DEXes
  (`Filter$CheckBox(String,boolean,int,DefaultConstructorMarker)`,
  `Filter$Select(String,Object[],int,int,DefaultConstructorMarker)`,
  `Filter$Separator(String,int,DefaultConstructorMarker)`,
  `Filter$Text(String,String,int,DefaultConstructorMarker)`,
  `Filter$TriState(String,int,int,DefaultConstructorMarker)`,
  `Page(int,String,String,Uri,int,DefaultConstructorMarker)`, …) — the shim classes
  replicate the exact default-value shapes.
* Network: `NetworkHelper.getClient()`, `OkHttpExtensionsKt.await/awaitSuccess(Call,Continuation)`,
  `RequestsKt.GET$default(String,Headers,CacheControl,int,Object)`.

## KNOWN-MISSING (shim surface)

* `eu.kanade.tachiyomi.network.JavaScriptEngine.evaluate(script)` — shipped for ABI
  completeness but always throws `ShimNotSupportedException` naming the member. Not
  referenced by the audited DEXes. A real implementation needs a JS engine (QuickJS).
* Network "util" surface from the task brief — `parseJsoup`, `parseAs`,
  `parseAsJsoupList`, `parseAsSrcDocstring`, `parseAsProtoBytes`, `JavaNetClient`,
  `eu.kanade.tachiyomi.util.*` — **verified NOT referenced** by any of the three
  audited DEXes (they call jsoup/kotlinx-serialization directly); extensions-lib v1.6
  does not declare them. If a future extension references them, add shims then.
* `SManga`/`SChapter` serialization (`@Serializable`) is not part of the linked ABI;
  `memo: JsonObject` uses plain kotlinx types.

## Shim implementation notes

* Module `:core:extension-api` (Android library, namespace `com.yomira.core.extension.api`,
  classes under `eu.kanade.tachiyomi.*` for link compatibility; 40 `.class` files / 23
  declared classes + companions). Mirrors extensions-lib v1.6 + Mihon behaviors:
  Mihon `generateId` (MD5 of `"name/lang/versionId"`, big-endian, sign bit cleared),
  `headersBuilder` UA default, `imageRequest`, `setUrlWithoutDomain` (URI-decoded path
  + query), `SMangaImpl`/`SChapterImpl` defaults.
* Network shims delegate to the host: `ShimServiceLocator.configure(client, userAgent?)`
  supplies the instrumented `OkHttpClient`; `NetworkHelper.client` fails fast with a
  typed `ShimNotSupportedException` naming the member until configured.
* `consumer-rules.pro` keeps `eu.kanade.tachiyomi.**` unrenamed through app release
  minification.
* App wiring: `:app` depends on the module (shims compile into the debug APK —
  verified present in `app-debug.apk` dex); unused at runtime until the host lands.
